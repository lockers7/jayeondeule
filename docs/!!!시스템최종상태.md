## 🔌 의존성 주입(DI) 훅

하위 계층이 상위 서비스를 필요로 하는 경우, **상위 계층(startup.py)이 주입**하는 방식으로 계층을 준수합니다.

| 훅 위치 | 주입 대상 | 주입자 |
|---------|-----------|--------|
| `src/postgresql/connection.py::set_mcp_query_fn()` | `mcp_client.postgres_query` | `startup.py` |
| `src/chroma/operations.py::set_embed_fn()` | `ai.embedder.embed_text` | `startup.py` |
| `src/control/task_scheduler.py::setup_default_jobs(opinet_collect_func=, lotto_collect_func=)` | `opinet.collect_all`, `lotto.update_lotto_db` | `startup.py` |

이 패턴 덕분에:
- L6(data/control)이 L5(ai)를 참조하지 않음
- 테스트 시 Mock 주입 용이
- startup.py가 바인딩의 단일 원천

## 🧩 3단계 AI 파이프라인 (핵심 워크플로우)

```
사용자 질문
    ↓
[1단계] question_analyzer.py
  - LLM이 JSON 계획 생성: {question_type, intent, required_data, multi_house, house_ids}
  - 인사/잡담은 규칙 기반 빠른 분류 (인사 fast_classify)
    ↓
[2단계] data_collector.py
  - required_data 순차 실행 (fan-out: multi_house=true 시 house_id별로 확장)
  - 중복 방지 key: (tool_name, query|url|farm_id|house_id|data_type|file_name)
  - 수집 데이터 충분성 LLM 검증 → 부족 시 1라운드 보충 수집
  - Rule-based 통과: 수집 바이트 ≥ 6000 시 LLM 검증 스킵
    ↓
[3단계] answer_generator.py
  - 수집 데이터 + 1단계 분석 + 대화 맥락으로 LLM 답변 생성
  - <USED_SOURCES> 태그로 LLM이 사용한 출처만 표시
  - URL 환각 제거 + 응답 유형 자동 판별
    ↓
스트리밍 응답
```

## 🐞 본 세션에서 해결한 주요 이슈

### 1. multi_house fan-out 실패 ⭐ (최근)
- **현상**: "각 재배사 릴레이 상태" 질의 시 1호만 응답
- **원인**: `data_collector._exec_key`가 `query`/`url`만 포함 → house_id 다른 태스크가 동일 key로 중복 판정
- **수정**: `_exec_key`에 farm_id/house_id/data_type 포함 (`data_collector.py:152`)

### 2. raspi_02 릴레이 극성 반전
- **현상**: 기동 시 모든 릴레이 ON 상태 (역동작)
- **원인**: raspi_02 릴레이 모듈은 active-high인데 #01 코드(active-low)를 그대로 복사
- **수정**: init `gpio_write(pin, 0)`, output_control `1 if status else 0` (`raspi/#02/gpio/gpio_control.py`)

### 3. raspi_02 DB IndexError
- **현상**: 서비스 1초 주기 크래시
- **원인**: DB는 relay_*_flag 16개 컬럼 / 2호 RELAY_GPIO는 15개 → `range(USING_RELAY_CNT)`로 리스트 만들면 1개 부족
- **수정**: `range(16)` + `getattr(..., False)` 기본값 (`raspi/#02/sql/sql_control.py`)

### 4. 시리얼 포트 부재
- **현상**: `FileNotFoundError: /dev/ttyS0`
- **원인**: 2호의 MH-Z19B는 `/dev/ttyAMA0` 포트 연결
- **수정**: `SERIAL_PORT = "/dev/ttyAMA0"` (`raspi/#02/sensor/sensor_config.py`)

### 5. raspi_02 네트워크 게이트웨이 오설정
- **현상**: 외부 DB 연결 실패 (`DNS resolution failed`)
- **원인**: NetworkManager `preconfigured` 연결의 게이트웨이가 `192.168.0.1`로 잘못 설정 (실제는 `192.168.0.254`)
- **수정**: `sudo nmcli connection modify preconfigured ipv4.gateway 192.168.0.254 ipv4.dns "192.168.0.254 1.1.1.1"`

### 6. AI 채팅 UI 모바일 세로 길이 과다
- **수정**: `web/frontend/src/pages/ai/AiChatPage.css` — `@media (max-width: 768px)` 에서 height 2/3

| pipeline Context dataclass | 전체 pipeline | 인자 9→1개 | **중간** (함수 시그니처 다 변경) |

### B. 새 raspi 추가 시 체크리스트

1. 하드웨어 IP 할당 (192.168.0.1xx)
2. 공유기 포트포워딩 (51xx → 192.168.0.1xx:22)
3. raspi에서 SSH 활성화 (`sudo raspi-config` → Interface → SSH)
4. NetworkManager 게이트웨이 확인 (`192.168.0.254`)
5. 소스 복사 (기존 비슷한 raspi의 `~/FarmUnits` 또는 `~/SmartFarm`)
6. `gpio/gpio_config.py` 수정:
   - RELAY_GPIO 배열 (실제 배선 순서)
   - RELAY_NAMES (웹 UI 릴레이 번호 대응 장치명)
7. `gpio/gpio_control.py` 극성 확인:
   - active-low (raspi_01/03 스타일): init True, output `0 if status else 1`
   - active-high (raspi_02 스타일): init 0, output `1 if status else 0`
8. `sensor/sensor_config.py` 시리얼 포트:
   - `/dev/ttyAMA0` (Pi4/Pi5 표준) 또는 `/dev/serial0` (심볼릭 링크)
9. `.env`의 `FARM_HOUSE_ID` 설정
10. systemd 서비스 경로 확인 (`/etc/systemd/system/jayeondeule_ctrl.service`)
11. `agri_ai_core/api/rpi_router.py::_RPI_PORT_MAP`에 포트 등록

### C. 버그 조사 체크포인트

| 증상 | 1차 체크 |
|------|---------|
| 서비스가 계속 죽음 | `journalctl -u jayeondeule_ctrl -n 100` → Traceback 추적 |
