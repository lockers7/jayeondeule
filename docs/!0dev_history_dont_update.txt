[회원관리]
회원과리 정보기능을 추가하라.
- agri_ai_core와 쇼핑몰 회원 테이블은 별도로 관리하라
  단, 시스템관리자로 로그인시는 모든 사이트 관리 가능하다.
- 이후 agri_ai_core와 쇼핑몰의 모든 정보는 별도로 테이블 구성하라.
- 쇼핑몰 테이블에는 모두 farm_id를 추가하여 농장별로 별도 기능으로 구성해서,
  쇼핑몰별 관리자/일반회원, 제품 정보를 관리 하도록 하라.
1. 시스템 관리자 회원 
   - 첫라인 자연들에 옆에 농장관리 아이콘을 추가하고 lockers7.iptime.org 링크를 걸고,
     농장관리(agri_ai_core)에도 쇼핑몰 아이콘을 추가하고 lockers7.iptime.org:5100 링크를 걸어서 서로 이동가능하게 하라.
   - 쇼핑몰 관리자 관리(farm_id, shop_usr_id, 회원등급(쇼핑몰관리자), 성명, 회원상태(정상, 삭제)
2. 쇼핑몰관리자 회원
   - 제품정보관리(farm_id, 제품번호, 제품명, 제품 이미지, 주문가능수량, 제품설명, 가격 등 상품의 구매를 위한 상세 항목)
   - 일반회원별 주문내역(farm_id, shop_usr_id, 주문일자, 주문상품, 수량, 가격, 연락처, 배송지 주소, 주문상태(주문, 발송대기, 발송)주문일자, 발송대기일자, 발송일자, 구매요구사항) 
   - 일반회원 주문 정보관리(farm_id, shop_usr_id, 제품번호, 발송대기, 발송, 취소, 사유(취소등 특이사항))
3. 쇼핑몰일반 회원
   - 회원관리(farm_id, shop_usr_id, 회원등급(일반), 성명, 회원상태(정상, 탈퇴), 전화번호, 주소, 가입일자, 탈퇴일자)
   - 내 주문 내역 리스트(구매제품(번호, 명), 구매일자, 결제여부, 진행상태)
   - 내 주문 관리(구매제품(번호, 명), 구매취소, 결제여부)
추가로
1. 테이블 설계 보완
회원 테이블 (shop_user)
현재 설계에 추가할 항목:

이메일 — 비밀번호 찾기, 주문 확인 메일 발송용 (필수)
비밀번호 (해시) — 로그인을 위해 필요 (현재 누락)
배송지 주소 — 회원정보에 기본 배송지를 저장하면 주문 시 자동 입력 가능
마지막 로그인 일자 — 휴면 계정 관리용
주문 테이블 (shop_order)
현재 설계에 추가/분리할 항목:

주문번호(order_id) — 주문 고유 식별자 (현재 누락)
총 결제금액 — 주문 시점의 가격 고정 (상품 가격 변동 대비)
결제방법 — 무통장입금, 계좌이체 등
입금확인일자 — 무통장입금 시 입금 확인 관리
운송장번호 — 발송 시 배송 추적용
주문상품 테이블 분리 필요
현재 주문에 상품 정보가 섞여 있습니다. 주문(order)과 주문상품(order_item)을 분리해야 합니다:


shop_order: 주문번호, 회원, 배송지, 결제정보, 주문상태...
shop_order_item: 주문번호, 제품번호, 수량, 단가 (1:N 관계)
→ 한 번에 여러 상품을 주문할 수 있어야 합니다.

2. 주문 상태 흐름 개선
현재: 주문 → 발송대기 → 발송

제안:


주문접수 → 입금확인 → 상품준비 → 발송완료 → 배송완료
                ↘ 주문취소
                     ↘ 환불처리
입금확인 단계 추가 — 무통장입금 시 필수
배송완료 추가 — 구매 확정과 연결
취소/환불 상태 분리 — 단순 취소 vs 발송 후 환불은 다른 프로세스
3. 회원등급 체계 개선
현재: 시스템관리자 / 쇼핑몰관리자 / 일반

제안:

등급	권한	비고
SYSTEM_ADMIN	모든 farm_id 접근, agri_ai_core 관리	기존 agri_ai_core의 ADMIN과 동일 계정
SHOP_ADMIN	자기 farm_id의 상품/주문/회원 관리	농장별 1명+
MEMBER	주문, 내 정보 관리	일반 회원
4. 제품 테이블 보완
현재 설계에 추가할 항목:

판매상태 (판매중, 품절, 판매중지) — 주문가능수량=0과 별도로 관리
카테고리 — 건조원물, 절편, 분말, 선물세트 등
원산지 — 식품 표시 의무
유통기한/제조일 — 식품 필수 정보
정렬순서 (sort_order) — 상품 노출 순서 관리
등록일자, 수정일자 — 이력 관리
5. 인증 체계 관련
중요 포인트:

agri_ai_core(Spring Boot JWT)와 쇼핑몰은 별도 인증 시스템이므로, 시스템관리자가 양쪽 모두 접근하려면:
방법 A: 각각 별도 로그인 (간단, 현재 구조에 적합)
방법 B: SSO(Single Sign-On) 구현 (복잡하지만 편리)
권장: 방법 A — 각 사이트에서 별도 로그인하되, 아이콘 링크로 쉽게 이동
6. 전체 테이블 구조 제안

shop_user        — 회원 (farm_id, shop_usr_id, 등급, 비밀번호, 성명, 전화, 이메일, 주소, 상태, 가입일...)
shop_product     — 상품 (farm_id, product_id, 상품명, 이미지, 가격, 재고, 카테고리, 판매상태, 설명...)
shop_order       — 주문 (farm_id, order_id, shop_usr_id, 총액, 결제방법, 배송지, 주문상태, 각종 일자...)
shop_order_item  — 주문상품 (order_id, product_id, 수량, 단가)

[쇼핑몰]
농장에는 실시간 스트리밍으로 농장 전경을 보여주고 재배사 소개에도 시시간 스트리밍으로 각 재배사의 상황버섯 생육 모습을 보여주는 기능도 포함해서  시스템 기본 구성을 구축하라.
- 상세 페이지 디자인 레이아웃
- 자사몰을 현재 프로젝트(React+Spring Boot)에 추가 구축
- 이후 기본 구성에 포함될 이미지 등은 준비해서 배치 하겠다. 현재는 임의 이미지를 사용해서 구축하라.
- 현재 시스템에 농장관리 시템이 웹으로 구축 되어 있다. 여기에 추가로 메인 폴더는 shop으로 추가 하되, 향 후 다른 서버로 쉽게 이전 가능하도록 하라..
- 쇼핑몰 접속 경로는 lockers7.iptime.org:5100 으로 진행하라.



상황버섯을 재배하는 스마트팜 시스템을 구성하고 상황버섯을 시스템으로 키우고 있다..
생산한 상황 버섯을 판매하는 쇼핑몰을 구축하고자 한다.
쇼핑몰을 구축하는데 아래의 내용으로 진행하려 하는데, 더 자세히 필요한 쇼핑몰 구축 방법, 구성내용 등을 조언하라.

- 현재 국내의 상황버섯 판매 사이트를 참고 
- 농장 소개
- 재배사 소개
- 시스템 생산이라는 부분 강조
- 생산한 상황버섯 이미지, 가격 등 전시 및 구매 유도 
- 판매 가격은 무통장 입금, 계좌 이체로 진행하고 향후 카드 결재 추가
- 위의 내용으로 쇼핑몰을 구성하고 블로그, 다른 대현 포털 쇼핑몰과 연동 고려
