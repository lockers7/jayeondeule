## 1. 릴레이 제어 관련 주요 함수

### 1.1 `relay_manager.py::auto_control_by_environment()`

**위치:** `agri_ai_core/control/relay/relay_manager.py:255-336`

**기능:** 센서 데이터 기반 릴레이 자동 제어

**주요 제어 로직:**

#### 1.1.1 온도 기반 제어

```python
def auto_control_by_environment(farm_id, house_id, sensor_data, optimal_conditions):
    current_hour = datetime.now().hour
    is_daytime = 6 <= current_hour < 18  # 주간: 06:00-18:00

    indoor_temp = sensor_data.get("indoor_temperature", 0)
    optimal_temp = optimal_conditions.get("temperature", {})

    # 주간/야간 구분
    if is_daytime:
        temp_min = optimal_temp.get("day", {}).get("min", 18)   # 기본값: 18℃
        temp_max = optimal_temp.get("day", {}).get("max", 28)   # 기본값: 28℃
    else:
        temp_min = optimal_temp.get("night", {}).get("min", 15) # 기본값: 15℃
        temp_max = optimal_temp.get("night", {}).get("max", 22) # 기본값: 22℃

    # 온도가 낮으면 → 히터 켜기
    if indoor_temp < temp_min:
        - indoor_heater_flag = True   # 열풍기 ON
        - water_heater_flag = True    # 물가열기 ON

    # 온도가 높으면 → 환풍기 켜기, 히터 끄기
    elif indoor_temp > temp_max:
        - exhaust_fan_flag = True     # 배출환풍기 ON
        - indoor_heater_flag = False  # 열풍기 OFF
```

#### 1.1.2 습도 기반 제어

```python
    indoor_humidity = sensor_data.get("indoor_humidity", 0)
    optimal_humidity = optimal_conditions.get("humidity", {})

    # 주간/야간 구분
    if is_daytime:
        humidity_min = optimal_humidity.get("day", {}).get("min", 60)   # 기본값: 60%
        humidity_max = optimal_humidity.get("day", {}).get("max", 80)   # 기본값: 80%
    else:
        humidity_min = optimal_humidity.get("night", {}).get("min", 65) # 기본값: 65%
        humidity_max = optimal_humidity.get("night", {}).get("max", 85) # 기본값: 85%

    # 습도가 낮으면 → 가습기 켜기
    if indoor_humidity < humidity_min:
        - fog_occurs_flag = True      # 분사펌프 ON

    # 습도가 높으면 → 환풍기 켜기, 가습기 끄기
    elif indoor_humidity > humidity_max:
        - exhaust_fan_flag = True     # 배출환풍기 ON
        - fog_occurs_flag = False     # 분사펌프 OFF
```

#### 1.1.3 조명 제어

```python
    # 주간(06:00-18:00)에만 조명 켜기
    if is_daytime:
        - lighting_flag = True
    else:
        - lighting_flag = False
```

**⚠️ 문제점:**
- **이 함수는 정의되어 있지만 실제로 호출되는 곳이 없습니다!**
- 스케줄러에 등록되어 있지 않음
- API 엔드포인트에서도 호출되지 않음

**house_id별 차이점:**

`mappers.py::get_relay_mapping()`:
```python
def get_relay_mapping(house_id=None):
    if house_id == 2:
        return RELAY_FIELD_MAPPING_E  # 2호 재배사용
    return RELAY_FIELD_MAPPING         # 1호/3호 재배사용
```

**모든 재배사 공통:**

**1호 재배사 특수 처리:**
```python
# 1호 재배사 열풍댐퍼(relay_15st_flag)는 항상 ON 유지
heater_valve_on = (str(house_id) == "1")

# ... 사용자 설정 적용 후 ...

# 1호 재배사 열풍댐퍼 강제 ON (덮어쓰기 방지)
if str(house_id) == "1":
    relay_values["relay_15st_flag"] = True
```

#### 1.2.3 별칭 매핑 (공통)

```python
alias_mapping = {
    "lighting_flag": "relay_7st_flag",     # 조명토글
    "irrigation_flag": "relay_8st_flag",   # 관수밸브
}
```

**⚠️ 주의:**
- 이 별칭은 1호/3호 재배사 기준입니다
- 2호 재배사는 실제로 `relay_5st=조명`, `relay_6st=관수밸브`를 사용하지만, 서버 코드는 이를 인식하지 못합니다
- **라즈베리파이 코드(raspi/v1)가 house_id=2로 데이터를 저장하므로, 서버에서 조회 시 MAPPING_E를 사용하여 올바르게 해석됩니다**

### 1.3 `schedule_control.py::control_lighting_schedule()` / `control_irrigation_schedule()`

**위치:** `agri_ai_core/control/relay/schedule_control.py`

**기능:** 시간 기반 조명/관수밸브 스케줄 제어

**특징:**

- **1분마다 스케줄러에서 자동 실행**

**house_id 차이:**
- **동일한 로직 사용**
- 테이블에서 house_id로 필터링하여 각 재배사별 스케줄 적용

## 2. house_id별 릴레이 매핑 차이

### 2.1 RELAY_FIELD_MAPPING (1호/3호 재배사용)

|-----------|-----------|--------|------|
| relay_1st_flag | 0 | 물가열기 | 물 온도 조절 |
| relay_2st_flag | 1 | 분사펌프 | 포그 분사로 습도 상승 |
| relay_3st_flag | 2 | 배수밸브 | 물 배출 |
| relay_5st_flag | 4 | **흡기팬** | 외부 공기 흡입 |
| relay_6st_flag | 5 | **배기팬** | 내부 공기 배출 |
| **relay_7st_flag** | **6** | **조명토글** | 조명 제어 |
| **relay_8st_flag** | **7** | **관수밸브** | 관수밸브 제어 |
| relay_9st_flag | 8 | 열풍기 | 내부 온도 상승 |
| relay_10st_flag | 9 | 순환댐퍼 | 공기 순환 |
| relay_11st_flag | 10 | 흡기댐퍼 | 흡입 밸브 |
| relay_14st_flag | 13 | 배기댐퍼 | 배출 밸브 |
| relay_15st_flag | 14 | **열풍댐퍼** | **1호 전용: 항상 ON** |

### 2.3 주요 차이점 정리

| 항목 | 1호/3호 재배사 (MAPPING) | 2호 재배사 (MAPPING_E) |
|------|----------------------|---------------------|

| **열풍기** | relay_9st | relay_13st |
| **열풍댐퍼** | relay_15st | relay_14st |

## 3. 현재 운영 중인 제어 방식

### 3.1 스케줄 기반 제어 (현재 운영 중 ✓)

**대상:** 조명, 관수밸브
**주기:** 매 1분
**데이터 소스:** `light_irrigation_s_setting` 테이블
**로직:** `agri_ai_core/control/relay/schedule_control.py`

**동작 방식:**
1. 매 1분마다 `control_all_schedules()` 실행
2. 각 재배사의 조명/관수밸브 스케줄 조회
3. 현재 시간이 `strt_time ~ fnsh_time` 범위 내인지 확인
4. 범위 내이면 해당 릴레이 ON, 범위 밖이면 OFF
5. `set_relay_value()`로 데이터베이스에 저장

**house_id 차이:**
- **없음** (동일한 로직, 테이블에서 house_id로 필터링만 수행)

### 3.2 센서 기반 자동 제어 (현재 미운영 ❌)

**함수:** `auto_control_by_environment()`
**상태:** 정의만 되어 있고 실제 호출되지 않음

**만약 운영된다면 예상되는 동작:**

#### 3.2.1 온도 제어

**조건:**
- 주간(06:00-18:00): 18-28℃ 유지
- 야간(18:00-06:00): 15-22℃ 유지

**제어:**
- 온도 < 최소값 → `indoor_heater_flag=ON`, `water_heater_flag=ON`
- 온도 > 최대값 → `exhaust_fan_flag=ON`, `indoor_heater_flag=OFF`

**house_id 차이:**
- **없음** (동일한 로직)
- 단, 1호 재배사는 `relay_15st_flag`(열풍댐퍼)가 항상 ON으로 보호됨

#### 3.2.2 습도 제어

**조건:**
- 주간: 60-80% 유지
- 야간: 65-85% 유지

**제어:**
- 습도 < 최소값 → `fog_occurs_flag=ON` (분사펌프)
- 습도 > 최대값 → `exhaust_fan_flag=ON`, `fog_occurs_flag=OFF`

**house_id 차이:**
- **없음** (동일한 로직)

#### 3.2.3 조명 제어

**조건:**
- 주간(06:00-18:00): ON
- 야간(18:00-06:00): OFF

**제어:**
- `lighting_flag` = `is_daytime`

**house_id 차이:**
- **잠재적 문제 있음!**
- 코드는 `lighting_flag`를 `relay_7st_flag`로 변환
- 2호 재배사는 실제로 `relay_5st_flag`가 조명인데, 잘못된 릴레이를 제어할 수 있음

## 4. 수동모드에서의 실제 동작

### 4.1 현재 상황

**수동모드(`mnul_ctrl_flag = True`)일 때:**

1. **스케줄 기반 제어는 계속 동작** ✓
   - `control_all_schedules()`는 수동모드 여부를 체크하지 않음
   - 조명/관수밸브 스케줄은 수동모드에서도 실행됨

2. **센서 기반 자동 제어는 동작하지 않음** ❌
   - `auto_control_by_environment()` 함수가 호출되는 곳이 없음
   - 스케줄러에 등록되어 있지 않음

3. **LLM 기반 제어는 가능** ✓
   - `relay_controller.py::detect_and_execute_relay_commands()`
   - 사용자가 채팅으로 "물가열기 켜" 등의 명령 입력 시 실행
   - 수동모드와 무관하게 동작

### 4.2 결론

**현재 agri_ai_core에서는:**
- ✓ 시간 기반 조명/관수밸브 스케줄 제어만 자동 실행 중
- ❌ 센서값 기반 온도/습도 자동 제어는 구현되어 있지만 사용되지 않음
- ❌ 수동모드/자동모드 구분에 따른 제어 차이는 없음

**house_id별 차이:**
- ✓ 릴레이 매핑 차이만 존재 (MAPPING vs MAPPING_E)
- ✓ 1호 재배사 열풍댐퍼 보호 로직만 특수 처리
- ❌ 센서값 기반 제어 로직의 차이는 없음 (실행 자체가 안 되므로)

## 5. 향후 개선 방안 (참고용)

### 5.1 센서 기반 자동 제어 활성화

만약 `auto_control_by_environment()`를 실제로 사용하려면:

1. **스케줄러에 등록:**
   ```python
   # task_scheduler.py::setup_default_jobs()에 추가
   if auto_control_func:
       add_job(
           job_id="auto_environment_control_job",
           func=auto_control_func,
           trigger_type="interval",
           minutes=5  # 5분마다 실행
       )
   ```

2. **수동모드 체크 추가:**
   ```python
   def auto_control_wrapper(farm_id, house_id):
       # 수동모드인지 확인
       status = get_single_house_status(farm_id, house_id)
       if status and status.get("operation_mode") == "수동모드":
           # 수동모드일 때만 실행
           auto_control_by_environment(...)
   ```

3. **house_id별 릴레이 매핑 수정:**
   ```python
   # 2호 재배사용 별칭도 추가
   if house_id == 2:

           "lighting_flag": "relay_5st_flag",
   ```
