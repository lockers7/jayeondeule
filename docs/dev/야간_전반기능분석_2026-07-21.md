## 축① 로컬AI·서버·시스템 리소스 접근 (조사 완료, 라이브 검증)

**리소스 접근 도구 — 전부 구현·라이브 작동 확인:**
- `get_server_resources`(tools_resources.py:130): CPU(20코어·load), 메모리(94GB), 디스크, **GPU 2장 실측**(RTX 5060 Ti 13017/16311MiB·42℃), services. psutil+nvidia-smi.
- `list_services`(15개), `service_status`, `restart_service`(재기동 전용 6개, stop 미구현·sudo NOPASSWD restart만), `get_system_status`(농장 운영상태만·리소스 아님).
- `write_script`/`run_script` 샌드박스: scripts/llm/ 한정·비root(uid=1000)·timeout·감사. 라이브로 psutil 시스템점검(프로세스 519개 열거) 성공 → 임의 파이썬으로 패키지·프로세스·파일 점검 가능.

**⛔ 최대 GAP — 리소스 접근은 채팅 AI 전용, 주기 Agent 에는 전무:**
- 주기 Agent 도구 15개(read6+write4+external5)에 **리소스/서비스/스크립트 도구 0개**.
- 즉 Agent 는 CPU·메모리·**GPU OOM**·서비스 다운 같은 **인프라 이상을 자율 감지·자가치유(restart_service) 불가**. 사람이 채팅으로 물어야만 드러남. (MEMORY 'MCP누수→Ollama OOM 실장애' 유형을 Agent 가 못 잡음)

**부수 결함:**
- get_server_resources 의 서비스목록이 _ALLOWED(6개)만 재사용 → list_services(15개)와 커버리지 불일치(nginx·PostgreSQL 등 누락).
- tools_definition.py:548 get_server_resources **description 오배치**(list_services 내용으로 채워짐) → 리소스 vs 서비스 질문 라우팅 혼동 소지.
- 비-root 경계는 양호(sudo 없음·stop 미구현).

## 축③ 자율 웹검색→저장판단→저장 체인 (핵심 질문, 조사 완료) ⭐

### 결론: 체인은 **(3)실제 저장에서 단절**. 자율 Agent는 웹에서 찾아 판단까지 하지만, **저장 도구가 없어 통지(send_user_alert)만** 하고 지식은 영구 저장되지 않는다.

**(1) 자율 웹검색 개시 — 부분 (능력 O, 자율 트리거 X)**
- Agent 는 웹도구 보유(search_web/mcp_call 등)하나, 유일한 자율 트리거인 기본 cron(`__default_cron__` 30분)은 "센서 읽고 릴레이 제어" 임무뿐 — 웹 언급 0.
- `_is_external_info_task()` 정규식에 **task 텍스트가 매칭될 때만** 외부검색 프롬프트로 라우팅. 기본 cron은 안 걸림 → 기본 사이클은 절대 웹검색 안 함.
- 웹검색은 **농장주가 채팅으로 구독 등록할 때만** 발생 = 지시 기반, 자율 아님. **"주기적 자율 웹스캔 루프는 존재하지 않음."**

**(2) 저장여부 자율 판단 — 부분 ('통지' 판단이지 '저장' 판단 아님)**
- CTRL_AGENT_EXTERNAL 프롬프트는 "유용한 핵심만 골라 send_user_alert 로 통지, 없으면 NO_ALERT" 판단 지시. 그러나 귀결이 **알림**이지 저장이 아님. "저장할 가치가 있는가" 판단 지시는 없음.

**(3) 실제 저장 — 미구현 (Agent 경로 단절)** ⛔ 핵심
- Agent TOOL_REGISTRY 15개에 지식저장 도구(save_domain_knowledge/manage_system_knowledge/save_lesson) **없음**(import 확정). write 도구는 set_relay/set_threshold/set_growth_stage/send_user_alert 4개뿐.
- 저장 도구는 **채팅 전용** — control/·ai_monitor_agent 에서 호출 0건. 채팅 save_domain_knowledge 도 **농장주 "학습해/저장해" 발화**로만 호출.

### 체인 단절 지점
자율 Agent(웹검색+판단 가능) ↔ 지식저장(채팅 전용) 이 **아키텍처상 분리**되어 연결된 적 없음. Agent 가 유용정보를 찾아도 → send_user_alert(카카오)로 끝 → **지식베이스 영구저장 안 됨.** 외부도구 설계 의도 자체가 "수집·판단→통지"로 저장은 범위 밖.

### 구현하려면(최소 3가지)
1. Agent 외부도구셋에 `save_domain_knowledge` 래퍼 추가(지식-write 카테고리 신설) → Agent 가 저장 능력 획득.
2. CTRL_AGENT_EXTERNAL 프롬프트에 "유용성 판단 후 통지 + save_domain_knowledge 로 저장" 단계 추가.
3. (진짜 자율개시) agent_scheduler 에 웹스캔 전용 기본 구독(`__default_web_scan__`) 부트스트랩 → 농장주 등록 없이 주기 실행.

**→ 농장주 질문 답변: "자율 웹검색→스스로 저장판단→저장" 체인은 현재 미구현/부분구현.** (검색+통지는 됨, 자율개시·자율저장은 안 됨)

## 축④ Agent 실시간 정보 전반관리 (조사 완료, 라이브 검증)

**Agent 가 완전 자율관리하는 실시간 정보 (라이브 확인, 3데몬 가동: scheduler/worker/event_listener):**

**판정**: 농장 내부 실시간은 사실상 전부 Agent 자율관리·라이브검증됨. "모든 실시간 정보" 미달은 **카메라 영상(실질)** + **의도분리된 시스템도구(정상)** 2축.

# ■ 종합 (Executive Summary) — 농장주 핵심질문 답변

## Q. "로컬 AI가 스스로 웹검색해서 농장운영 도움정보를 검색·저장판단·저장하고, Agent가 모든 실시간정보 관리 가능한가?"

### A1. 자율 웹검색→저장판단→저장 체인 = **부분구현 (핵심 미완)** ❌
| 단계 | 상태 | 근거 |
|---|---|---|
| 웹검색 능력 | ✅ 있음 | search_web·mcp_call 라이브 성공, Agent에도 결합 |
| **자율 개시**(농장주 지시 없이 주기 스캔) | ❌ 없음 | 기본 cron은 센서·제어 임무뿐. 웹검색은 농장주 구독 등록 시에만 |
| 유용성 판단 | △ 통지판단만 | CTRL_AGENT_EXTERNAL 은 "통지 여부" 판단이지 "저장 여부" 판단 아님 |
| **실제 저장** | ❌ 없음 | Agent 15도구에 지식저장 도구 부재 → 찾아도 send_user_alert(통지)로 끝, 영구저장 안 됨 |

**→ 즉 "스스로 검색은 하되(단, 농장주가 시켜야), 통지는 하지만, 스스로 저장은 못 한다."** 자율 Agent(검색가능)와 지식저장(채팅 전용)이 아키텍처상 분리돼 연결된 적이 없음.

### A2. Agent의 모든 실시간정보 관리 = **농장 내부는 완전, 2가지 GAP** △
- ✅ 센서·릴레이·제어결정·임계·알림·카카오 = 완전 자율 폐루프(라이브 검증, set_relay 167건·alert 76건 executed). 구독(임의 주기·intent) + 이벤트 즉시화(NOTIFY).
- ❌ **카메라 영상**: get_camera_view 채팅 전용, Agent 미포함 = 유일 실질 결함.
- ➖ 서버자원·로그·서비스·SQL·소스: 의도적 모드분리(Agent 범위 밖, 정상).

### A3. 리소스·외부접속 인프라 = **채팅 AI 완전, 외부접속 양쪽 실작동** ✅△
- 서버/시스템 리소스(CPU·메모리·GPU·디스크·서비스·스크립트): 채팅 AI 완전 구현·라이브. **단 Agent 는 리소스 사각지대**(GPU OOM·서비스다운 자율감지·자가치유 불가).
- 외부 URL/MCP: 채팅·Agent 양쪽 라이브 성공(korea-weather·pubmed·naver·searxng).

# ■ 미구현분 구현설계 (자율 웹검색→저장판단→저장)

**목표**: 농장주 지시 없이도 Agent 가 주기적으로 웹/MCP 를 스캔 → 농장도움 정보를 스스로 유용성·저장가치 판단 → 지식베이스(도메인 RAG)에 저장 → 채팅/제어가 자동 참조.

**1) Agent 에 지식저장 능력 부여** (GAP1)
- `tools_agent_external.py` 또는 신규 `tools_agent_knowledge.py` 에 `save_domain_knowledge` 래퍼(agent용) 추가 → run_agent TOOL_REGISTRY 병합. 단 read-only 원칙 유지 위해 "지식-write" 별도 카테고리로 명시(제어 write 와 구분).
